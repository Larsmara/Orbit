# Objectives

## Description
A scrollable objective tracker with a hybrid render model. For the **quest family** (quests, campaign, world quests, bonus, achievements, professions, monthly activities) Orbit removes Blizzard's modules and renders its own pooled widgets from C-API reads. For the **scenario/event block** (scenarios, dungeons, delves, M+, and zone UI-widget events) it reparents Blizzard's live `ScenarioObjectiveTracker` + `UIWidgetObjectiveTracker` into the top of our box, native cards + flyouts intact. Fully themed (fonts, colours, Orbit progress bars, borders, quest-type POI icons), Edit-Mode draggable, Visibility-Engine aware.

## Purpose
The old *quest* reparent-and-skin model tainted the WorldMap (see Gotchas). Rendering our own quest widgets from C-API reads is taint-free *and* gives full control over layout/scroll/theme, plus behaviours Blizzard lacks: per-section collapse persistence, combat auto-collapse, and current-zone quest / world-quest filtering. Scenarios stay native because re-rendering them would taint Blizzard's shared `UIWidgetManager` pool (M+/delve richness ships separately as `StatusWidget/MythicPlus`).

## Implementation
`ObjectivesPlugin.lua` owns `OrbitObjectivesContainer` (a `ScrollFrame` + `scrollChild` on UIParent), edit-mode/border/backdrop/content-fit height. `SuppressBlizzardTracker` schedules `ApplyBlizzardSuppression` **next-frame** (lands after Blizzard's own init/managed-layout/edit-mode restore): it `RemoveModule`s + `KeepAliveHidden`s the quest modules, `DetachNativeSystems` unhooks `ObjectiveTrackerFrame` from Blizzard Edit Mode (`defaultHideSelection`) and the right-managed layout (`ignoreFramePositionManager` + `layoutParent:RemoveManagedFrame`), then reparents the tracker into `scrollChild`. Refresh is a taint launder: events set a boolean via `ScheduleRefresh`, and a `RegisterUpdate` poll drains it into `FullLayout` (see Gotchas). `FullLayout` calls `BuildModel` then `LayoutContent`. `HookScenarioFlyouts` drops the scroll clip while a horizontally-opening scenario flyout (Delve Challenges / MawBuffs) is shown.

`ObjectivesModel.lua` runs a provider registry and buckets entries into the ordered `SECTIONS` (data in `ObjectivesConstants.lua`; titles reuse Blizzard's localized header globals). Providers read only C APIs: `ObjectivesQuestProvider.lua` (watch lists + current-map tasks → quests/campaign/WQ/bonus), `ObjectivesAchievementProvider.lua`, `ObjectivesScenarioProvider.lua` (non-M+ scenarios/delves — M+ is owned by `StatusWidget/MythicPlus`), and `ObjectivesTrackableProvider.lua` (recipes, monthly activities). The model owns the world-quest objective cache (Blizzard zeroes WQ objectives out-of-zone).

`ObjectivesRender.lua` pools rows + section headers of our own FontStrings/Textures/StatusBars, stacks them into the scroll child, and returns the content height. `ObjectivesSkin.lua` holds the pure styling primitives (POI colour/atlas decision trees, `ApplyBarStyle`, progress-label formatter, header separator, fonts) re-pointed to our entry records. `ObjectivesInteractions.lua` owns the shared secure quest-item overlay + click-to-super-track + header collapse. `ObjectivesEvents.lua` maps events → `ScheduleRefresh` + combat auto-collapse + WQ-cache invalidation. `ObjectivesZoneFilter.lua` manages the watch list (unchanged, watch-list based). `ObjectivesSettings.lua` builds the Layout / Behaviour / Colours schema.

## Gotchas
- **The taint that forced this rebuild:** Blizzard rendering the tracker's quest POI number-buttons writes the shared quest `ObjectCache` (`GetQuestClassification → QuestCache:Get`, first-access write); the WorldMap reads that same cache, so its protected `SetPassThroughButtons`/`SetPropagateMouseClicks` throw `ADDON_ACTION_BLOCKED` in combat. Fix: `RemoveModule` every quest-family module so they never render, and read classification via `C_QuestInfoSystem.GetQuestClassification` (a C API that does **not** write the cache). `AdventureObjectiveTracker` also emits POI buttons, so it too must be custom-rendered (not reparented) if re-added.
- **Removed-but-unrendered modules:** `BLIZZARD_REMOVE` strips `AdventureObjectiveTracker` (content-tracking collectibles: transmog/mount/decor/vendor/journal) and `InitiativeTasksObjectiveTracker` (housing neighborhood tasks) but there is **no provider for them yet** — that tracked content currently disappears. Re-adding it means new `CATEGORY`/`SECTIONS` entries + providers (`C_ContentTracking` / `C_NeighborhoodInitiative`), Adventure custom-rendered to stay POI-taint-safe.
- **The taint launder:** events only set `_refreshPending = true` (a plain boolean write never taints); the `RegisterUpdate` frame — created once on a clean stack and never referenced again — drains it into `FullLayout`, so `entry:Show()` always runs on a clean stack no matter how many tainted paths requested a refresh.
- **Combat-safe layout:** every widget is UIParent-descended (insecure), so `FullLayout` runs in combat — kill-counts update, auto-collapse applies. The only secure frame is the shared item overlay, which is *anchored* (never parented) over a row's hit-frame and mutated OOC-only, so rows stay insecure and can relayout during combat.
- **Edit Mode / managed layout:** the reparented `ObjectiveTrackerFrame` stays a Blizzard Edit-Mode system *and* a right-managed frame. `DetachNativeSystems` sets `defaultHideSelection` (no stray `.Selection` box under ours) and `ignoreFramePositionManager` + `RemoveManagedFrame` (so `ManageFramePositions`/`ManagedFrameMixin:OnShow` stop re-anchoring it); the `Show` hook re-ejects it because Blizzard re-adds on every show.
- **Scenario flyouts escape the box:** the Delve Challenges and MawBuffs flyouts open horizontally past our edge; `HookScenarioFlyouts` disables the scroll clip while one is shown (a `ScrollFrame` clips rectangularly — can't clip only vertically).
- **Disabled-plugin fallback:** when the plugin is disabled the suppression never runs; `RegisterBlizzardHider` + the Core VE `ObjectiveTracker` row still let the user hide Blizzard's native tracker, and `StatusWidget/MythicPlus` keeps its own scenario-block hide for that case.

## Secrets
Quest / objective / achievement / scenario data is plain Lua in and out of combat — no `issecretvalue` guards; progress-bar percentage math is safe.
